Rule entry of 18 October 2026, second update

R-2026-10-18-C. Fingerprint layout version 2

Entered 18 October 2026. From this date the fingerprint uses layout chr-entry-v2. It is built exactly as the chr-entry-v1 layout in rule A, except that the first line is the tag chr-entry-v2 and three more lines follow the fifteen fields of v1, in this order: hype_score, means_score, cost_score. Every entry now carries all three sub-scores, each MATCHED, MIXED, FAILED or OPEN. An entry not yet resolved reads OPEN.

The reason for the change: the v1 layout left the hype, means and cost sub-scores outside the fingerprint, so a sub-score could have changed without any fingerprint showing it. Layout v2 closes that gap. Any column added to the register later needs a new layout and a dated rule entry; until then, that column is outside the fingerprint and the rule entry says so.

The v1 manifest of 18 October 2026 is kept unchanged in the record. From this update a v2 manifest is published alongside it, named entry-hashes-v2 followed by the update, and every build checks the data against both. No v1 fingerprint changes. The v2 fingerprints are new numbers for the same entries, not corrections.

A second update on the same day carries a letter after the date, as in 2026-10-18b, so no published file is ever overwritten.
